# 传播语义标注指南

本指南对应 `annotations/schema.json` 1.0。模板用于后续基于真实观测的人工分析；仓库中的空白模板不是已完成标注，也不是任何真实案例的示例。标注仅用于独立语义评价或明确标记的演示，不得作为训练标签、主动查询依据、超参数选择依据或模型前向输入。

## 文件与状态

从 `annotations/blank-template.json` 和 `annotations/blank-report.md` 创建案例文件。空白 JSON 的 `status=draft`、空列表和 `null` 均有实际含义：尚未提供信息，不是零值。模板作者记为 `assistant`，依据记为 `template_only_no_case_analysis`。开始依据观测分析后，按实际参与者填写 `prepared_by`，并改为 `observation_based`。

`submitted` 表示标注材料已提交，不表示专家确认。专家状态独立记录；助手完成的分析通常仍是 `not_reviewed`。只有真实确认发生且具有确认人、带时区的时间和可追溯记录时，才使用 `confirmed`。校验器不能认证签名真伪，也不能判定科学解释为真。

完成提交需要案例 ID、D1/D2、真实窗口、时间原点、秒单位及来源清单 SHA256；需要实体目录和诚实的覆盖说明。禁止用示例日期、随机构造哈希或猜测实体填充正式标注。草稿中的时间可留空，但已填写的事件/证据记录必须有完整合法时间；不完整记录先保留在工作笔记中。

## 实体、标签与观测必须分离

`entities` 保留导出包中的稳定实体 ID、类型和候选资格，不得只留下模型选中的实体，也不得通过重新命名泄露根标签。`root_role` 只描述授权评价标签：`root`、`nonroot`、`unknown`。只有 `root_supervision.availability=complete_set` 且给出标签侧文件来源时，才能填写根/非根事实；标签不可用时全部保留 `unknown`。完整根集合可包含多个根，不得擅自压成单根。

`observation_state` 单独描述本窗口的观测：`detected`、`not_detected`、`unknown`。根实体可能未检测到症状，非根实体也可能有明显异常。`not_detected` 需要可检查的观测证据和覆盖范围，不能等同于“正常”；模态或时间覆盖缺失应保留 `unknown` 或在限制中说明。根标签不作为事件、时间先后或传播边的证据。

## 证据、时间与症状

每条 `evidence` 包含稳定 ID、模态、包内相对文件路径、原始文件 SHA256、可复查定位（行号/字段/片段/查询）、实体 ID、真实时间区间和分辨率。模态取 `metric`、`trace`、`log` 或 `topology`。路径不得包含盘符、绝对路径、`..`、网络共享地址或备用数据流。根标签侧文件不放进观测证据索引。

所有时间采用带时区的 RFC 3339 字符串；不要把未知采样分辨率伪造为零。`resolution_seconds` 为正数，事件区间应覆盖从采样或聚合中能够支持的时间不确定性，而不是人为压成一个精确时间点。全部证据/事件/症状区间必须位于声明的案例窗口内；若需要更多上下文，应重新声明并验证窗口。校验器只检查填写的区间，不能从源文件自动推断你的实际采样不确定性。

`symptoms` 记录实体、症状类别、模态、变化方向、物理时间区间和证据。幅度 `magnitude` 包含数值、单位、基线（可未知）及计算口径；无法量化时置为 `null`，在 `unknown_reason` 解释原因，不使用零占位。类别或方向未知同样需要说明。`events` 引用一个或多个症状，并保留可追溯证据；无可归类症状的观测事件可以保留空 `symptom_ids`，但正式提交仍须提供证据。

校验器检查 ID 唯一性、引用存在性、症状与事件实体的一致性及时间区间相交，以及事件/症状至少有一条证据与其实体及时间相符。实体观测状态的证据必须至少有一条涉及该实体；仅引用另一实体的观测不合法。症状模态必须有对应来源。文件哈希校验与内容解释是两件事；哈希一致不证明所引用行确实支持结论。

边与片段的证据引用也至少需要一条同时涉及所属事件实体、且与这些事件的时间包络相交。时间包络从最早事件开始延伸到最晚事件结束，因此两端事件之间的上下文证据可以保留。关系优先使用引用它的边的时间包络；没有边引用时使用端点实体事件的时间包络，没有相关事件时退回已声明的案例窗口。额外背景引用可以保留，但不能仅用无关实体或无关时间的证据支撑整个记录。这只是最低限度的跨记录对应检查，不要求一份文件证明全部端点，也不验证影响方向或因果解释。

## 关系、调用方向、影响方向

`relations.type` 支持 `call`、`placement`、`same_entity`、`other`。`source_entity`/`target_entity` 是关系端点，不能单凭字段顺序认定因果方向。调用关系单独记录 `call_direction`；非调用关系该字段为空。不同时间的同一实体可以拥有多个事件；`same_entity` 两端必须保持相同实体 ID。

`impact_direction` 与调用方向独立，允许相反；`impact_status` 为 `observed`、`hypothesized` 或 `unknown`。观测支持的影响解释必须说明具体症状和支持证据，不能仅引用调用存在、根标签或时间顺序。证据不足时使用假设或未知；未知状态下方向留空。`observed` 不等于通过干预实验确认了因果关系，报告应明确仍可能存在的共同原因和其他解释。

## 部分顺序、延迟与共享节点

每个片段通过 `event_ids` 引用唯一事件顶点，用 `edges` 保留关系、时间顺序、延迟、证据和未知原因。多个路径汇聚或分叉时共享事件顶点，不能复制相同事件来假装独立路径。

`temporal_order=before` 仅表示源事件区间严格早于目标区间：源结束时间小于目标开始时间。它不自动表示影响沿该方向传播。若区间重叠、相接或现有分辨率不足以区分，使用 `unknown`，保留该边，并将两个延迟边界均设为 `null`。记录分辨率不足的原因，不通过任意排序补齐路径。

已解析边的物理延迟区间由事件区间确定：

- 下界 = 目标开始时间 − 源结束时间。
- 上界 = 目标结束时间 − 源开始时间。

单位为秒。校验器要求与上述计算一致；不能未经证据收窄为精确延迟。更精细的可信观测应先反映到事件区间。

`ordered_paths` 必须列出解析顺序子图中的所有完整极大路径，即无法再向前或向后延伸的非空有序边路径。例如共享汇聚结构 A→C、B→C、C→D 对应 A–C–D 与 B–C–D；不能用 A–C、B–C、C–D 三个分段替代。C、D 各只有一个事件顶点。未知边不进入有序路径，但仍留在 `edges` 中；仅含未知边或局部单事件的片段可使用空 `ordered_paths`。平行关系的同一事件序列只列一次，关系差异保留在各自边记录中。解析顺序存在环时校验失败，不会静默截断路径。

`family`、`interpretation`、`certainty`、`evidence_refs` 和 `unknowns` 描述结构及解释范围。覆盖不足时允许正式提交空 `fragments`，必须明确说明不足原因。不要为了有图可画而发明完整传播链。

## 报告、图与结构化记录的对应

按空白报告依次填写覆盖、实体状态、症状、关系、部分顺序、片段和限制。报告中的每项传播判断应能定位到 JSON 片段/边 ID 和原始证据 ID；图中的节点与边使用同一 ID。图例必须说明每一种箭头的含义，区分时间先后、调用方向和影响假设，未知边使用明确标记。

提交前人工逐项核对报告—JSON—图—证据索引。当前校验器不会解析自然语言报告或图片，因此不能替代这项人工检查，也不能据其通过宣称图文已核验。

## 运行校验

在安装本项目及其依赖后，可从 Python 调用：

```python
import json
from pathlib import Path
from vast_v3.annotations import validate_annotation

document = json.loads(Path("annotation.json").read_text(encoding="utf-8"))
report = validate_annotation(document, for_submission=True, evidence_root=Path("case-package"))
for message in report.errors:
    print(message)
assert report.valid
print(report.artifact_files_verified)
```

草稿校验省略 `for_submission=True`；`status=submitted` 即使没有该参数也按提交规则检查。未提供 `evidence_root` 时只校验结构和跨字段一致性，警告会明确说明文件未检查；提供后检查文件实际存在、解析路径仍在包内且 SHA256 一致。空证据集不会得到“证据文件已验证”。即使所有检查通过，仍需真实来源审阅和专家判断；`warnings` 不能当作可忽略的免责声明删除。

仓库中的 `annotations/schema.json` 是专家可读规范，Python 包内携带同内容副本用于安装后校验；单元测试保证两份一致。更新字段时同步二者，并更新模板、校验器、测试和本指南。

## 独立的 30 + 30 评价案例

D1 和 D2 各预留 30 个独立语义评价案例，总计 60 个；两个人工演示案例必须排除。案例清单应在查看演示搜索预测之前冻结，按照预定规则处理重叠，不按模型表现挑选“好标”的案例。专家材料不包含预测排名、分数、TOP1 成败或模型生成的传播结论。结构化格式拒绝额外预测字段，但文件名、自由文本和其他附件仍须人工检查是否泄漏预测。

清单数量、冻结哈希、案例唯一性和演示排除属于清单工具的职责，不由单个案例 JSON 校验器证明。此模板不附带任何已标注案例、不占用这 60 个名额，也不代表相关清单已生成。独立语义标签必须存放在评价侧，不能回流训练或演示选择。
